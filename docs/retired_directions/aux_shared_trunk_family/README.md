# Aux / Shared-Trunk Family Summary

> Status: archived family summary / retired mechanism evidence bundle
> Role: consolidate the DSN aux-leg and shared-trunk mechanism chain into one archive entry point
> Current canonical entry: `docs/posttrain_pipeline.md`
> Reader note: this family did not become current repo mainline; any `ship`, `default`, `recommend`, or `mainline` wording inside detailed records is historical family-local language

## 1. Historical Question

This family tried to answer:

> can training-only auxiliary leg supervision improve the shared trunk without breaking downstream contract, and if not, what mechanism explains the failure?

## 2. Experiment Ladder

The detailed records in this bundle follow one compact ladder:

- DSN proposal and implementation scaffolding
- stripped-export contract verification
- matched three-arm real training verdict
- shared-trunk mechanism disambiguation (`E1/E2/E3`)
- epochwise / seed / gradient-path follow-ups (`E4/E5a/E5b/E5d/E6`)
- family closure note
- downstream reevaluation

## 3. Final Conclusions

- DSN aux-leg did not produce a justified repo-mainline feature
- the most useful family-local arm was `aux_detach`, but only as the least-bad family-local control, not as a repo-level default
- the primary near mechanism is extra aux pressure entering the shared trunk / shared interface variables
- the leading mechanistic form is a shared-trunk plasticity / capacity sink
- attach mismatch remains a modulator, not the primary explanation
- strong per-step sign conflict is downgraded
- supervision–rollout mismatch is also downgraded from the primary explanation

## 4. Why Archived

- this family is archived because the detailed DSN / shared-trunk chain is no longer a live feature-design track
- the family did not produce a justified repo-mainline feature
- what remains useful is the negative evidence and mechanism reading, not the feature proposal itself

## 5. Failure Analysis

The family failed as a product/mainline candidate because:

- the aux feature never produced a clean downstream-positive case
- `stage6` and `70a` did not establish a stable positive window worth preserving
- downstream reevaluation showed that even the least-bad family-local arm did not beat the baseline chain cleanly enough

## 6. What Remains Reusable

This bundle still matters as:

- interface-contract fragility evidence
- negative evidence against “just add auxiliary supervision on the current shared trunk”
- a near-mechanism argument for why frozen-donor / decoupled-corrector ideas may help
- a record of why train-time readability alone was not enough to justify feature promotion

It should not be used as a live feature recommendation.
